# Blog writing quality

Write like a person who wants to be understood, not admired.

## The rules

1. Never use a long word where a short one will do.
2. If it is possible to cut a word out, cut it out.
3. Never use the passive where you can use the active.
4. Never use a foreign phrase, a scientific word, or a jargon word if you can
   think of an everyday English equivalent.
5. Never use a metaphor, simile, or figure of speech you are used to seeing in
   print. If you've read it before, the reader has too.
6. Never use an em dash. Not one. Rewrite the sentence: split it, use a comma,
   use a colon, use parentheses. If the sentence falls apart without the em
   dash, the sentence was broken.
7. Break any of these rules sooner than say anything outright barbarous.

## Banned patterns (AI slop)

Delete on sight, no substitutions needed:

- "delve", "leverage", "robust", "seamless", "streamline", "empower",
  "supercharge", "unlock", "elevate", "harness", "landscape", "realm",
  "game-changer", "in today's fast-paced world"
- "It's not just X, it's Y" and every variant of that seesaw
- "Whether you're a X or a Y" audience pandering
- Throat-clearing openers: "In the world of...", "When it comes to...",
  "Let's face it", "We've all been there"
- Wind-down closers: "In conclusion", "At the end of the day",
  "The future is bright"
- Rhetorical question followed by its own answer ("So what does this mean?
  It means...")
- Rule-of-three adjective stacks ("fast, simple, and powerful")
- Exclamation points in body copy

## Edit pass (run on every draft)

1. Read each sentence aloud in your head. If you would not say it to a
   coworker at lunch, rewrite it.
2. Cut the first paragraph if the second paragraph works as an opener. It
   usually does.
3. Find every "is/are/was/were + past participle" and flip it active.
4. Count words per sentence. If three sentences in a row are the same length,
   vary one.
5. Replace every abstraction with the concrete thing: not "improved
   visibility", but "you can see which agent is stuck".
6. One idea per sentence. One argument per paragraph.
7. Search the draft for "—" and "–". The count must be zero.

## Voice notes for GitSpace posts

- The reader is a developer running coding agents. Assume competence; skip
  definitions of things they use daily.
- Claims come with proof: a screenshot, an interactive demo, a number. If a
  paragraph makes a claim without proof nearby, flag it.
- Name competitors plainly and fairly. Praise what they do well before
  showing the gap.
- Short declarative sentences carry the argument. Save the long sentence for
  the one place it earns its length.
