GitSpace / Agent Provenance

What if git blame could explain the conversation behind the code?

Agent Blame is a system for recording why code exists — not just who committed it. It captures conversational context from AI coding agents at edit time, preserves it across squash merges, and lets your team query the full reasoning chain behind any line.

SCROLL
The Problem

git blame tells you who. It cannot tell you why.

When AI agents write code, the reasoning lives in the conversation — the user's request, the agent's plan, the intermediate refactors. But once the branch is squashed and merged, all of that evaporates. You get one commit hash and a message.

The key insight: the unit of provenance is not the commit. It is the mutation event — each time an agent successfully changes code. Multiple events may land in a single commit, but the reasoning chain only exists in the pre-commit event history.

Lineage

How the system knows "introduced", "moved", and "refactored"

It compares pre-image and post-image states around each tool call. Classification comes from matching new hunks against prior recorded effects using text overlap, anchor context, blob hashes, and path heuristics. Not magic — evidence-based scoring.

How classification actually works

For each new hunk effect, the system searches prior recorded effects and scores candidates. The result is a confidence-weighted lineage edge — or no edge at all.

Strong signal → link
Exact text match
  removed fragment == earlier added fragment
  → high confidence move or supersede

Same anchors + partial overlap
  same file region, some tokens survive
  → high confidence refine

Path rename + similar text
  file moved, content mostly preserved
  → medium-high confidence move
Weak signal → break
Generic code shape only
  common patterns match many origins
  → no edge

Low token overlap + different anchors
  different region, different intent
  → no edge

Many equally plausible ancestors
  ambiguous origin
  → no edge (or tentative only)

Efficiency

How summaries are cached, not regenerated

Because events and lineage edges are immutable, large parts of the provenance graph are stable. Summaries are cached by content hash, composed incrementally, and only regenerated when new events extend a chain.

Level 1
Event Summary
One summary per mutation event. Computed once, cached forever.
cache[hash(event_payload)]
"Added signup validation after user requested safer signup handling."
Level 2
Chain Summary
One summary per lineage subgraph. Composed from event summaries.
cache[hash(node_ids + edge_ids)]
"Introduced signup validation, extracted into shared helper, then hardened error handling with typed errors."
Level 3
Query Explanation
Built on demand from cached summaries. Uses AI only for compression.
cache[chain_hash + anchor]
"This validation exists because signup needed hardening; the logic was extracted into a shared module and later given typed error handling."

When a new event extends a chain: only the new tail needs summarization. The existing chain summary stays valid. Composition is deterministic when possible; AI is only invoked for compression or conflict resolution.
